Claude Sonnet 4.5 将在 11 月 30 日下线：迁到 Sonnet 5.5 的清单

网页里聊 Claude，和 API 里写死的 model ID 被关，是两件事。

2026 年 11 月 30 日，claude-sonnet-4-5-20250929（以及别名 claude-sonnet-4-5）会从 Anthropic 自家平台上直接不可访问。今天起大约还有六周。仓库、定时任务、第三方封装里要是还钉着它，别等 11 月底再改。

官方退役表

点击查看官方退役表

官方推荐替换是 claude-sonnet-5-5。换字符串不等于能直接上线：一批旧写法会直接 400，还有一批不报错但行为变了。

有人希望 Anthropic 把 4.5 留成永久 legacy，情绪很真实；工程上更稳的是默认它会关，把调用面先迁掉。

谁需要现在动手

情况 要不要折腾
代码 / 环境变量 / Agent 配置里写死了 claude-sonnet-4-5 或带日期的快照 要，优先
自建 Bot、凌晨定时摘要、Zapier / 中间层还在调 4.5 要（这类最容易漏）
只在 claude.ai / Claude Code 用订阅聊天，从不碰 API model ID 这波不用管 API 退役表
走 Amazon Bedrock / Google Cloud 同名模型 要核对该云自己的退休日，别抄 Anthropic 表

国内想稳定用 Claude Pro、订阅和 API Key 仍是两本账。订阅升级可看 cnmclaude.com，站内 Pro 开通步骤见 Claude Pro 升级教程。

有人实测觉得 5.5 在循环任务上又快又省，适合当主力干活模型；

但同文在新分词器下大约会多出约 30% token，再加默认会开 thinking，账单要按自己业务重测，别只看单价。

迁移指南：token 与 cost

五步照做（够用版）

  1. 先盘点谁还在调 4.5
    Claude Console → Usage → Export，看 CSV 里按 API Key / 模型的用量。再全仓搜 claude-sonnet-4-5、20250929。凌晨跑的 CRM 摘要、评测脚本、外包临时 Key，最容易漏。
  2. 改 ID，并显式设 effort
    目标 ID：claude-sonnet-5-5。4.5 没有 effort；5.5 建议在 output_config.effort 里设，例如 medium / high。默认偏 high，别以为“不传就跟以前一样”。
  3. 拆掉会直接 400 的旧参数（从 4.5 过来最常踩）
旧习惯（4.5 还能用） 5.5 怎么处理
最后一条 assistant prefill 去掉；格式用 structured outputs / 工具，或改写进 user
tool_choice 为 any / 指定 tool 改 auto；需要时给工具加 strict: true，并在 prompt 里说明何时调用
非默认 temperature / top_p / top_k 删掉
thinking: {type: enabled, budget_tokens: N} 改 adaptive + output_config.effort
thinking: {type: disabled} 改 thinking: {type: “between_tools”}（且 effort 勿用 xhigh/max）

完整清单以官方 Sonnet 5.5 migration guide 为准。Claude Code 里也可用 /claude-api migrate 辅助改仓库。

4.处理“不报错但会变”的行为

  • 以前不传 thinking = 不思考；现在默认会开 adaptive thinking。
  • 响应可能先出现 thinking 块，硬读 content[0].text 会挂，按 type 取 text。
  • 工具循环要把 thinking 块原样回传。
  • max_tokens 覆盖 thinking + 正文，thinking 按输出计费。
  • 还活着时做 A/B，并准备“关了之后的回滚”

用同一批真实任务（正常 / 边界 / 已知失败）并跑 4.5 与 5.5，记准确率、工具调用、延迟、token、人工复核时间。11 月 30 日后没法再拿 4.5 当基线。回滚也不能再指回 4.5——提前备好另一台已测过的在役模型、上一版 prompt，或短暂人工兜底。

拖到报错再改，等于没有迁移计划。小团队尤其容易低估：业务方只觉得“摘要没了”，第一反应是问人，不是翻 model ID。

踩坑

  • Anthropic 和 Bedrock / GCP 不是同一天。 日期表只覆盖 Claude API、Claude Platform on AWS、Foundry；Bedrock、Google Cloud 看各自模型表。
  • 别名会连坐。 以为只钉了带日期快照、其实配置里写的是 claude-sonnet-4-5，一样会挂。
  • Prefill / 强制 tool / 采样参数会秒死。 这是好事：测试一跑就暴露。真正危险的是格式漂移、工具顺序变了、拒答边界变了——请求 200，业务却坏了。
  • 单价降了 ≠ 单次任务更便宜。 约 30% 更多 token + 默认 thinking，必须用自己的日志重算。
  • 订阅聊天 ≠ API 快照。 只开 Pro 在网页用，和代码里钉死 4.5，是两条线；别把“我 Claude 还能聊”当成“API 也安全”。

我的建议

你的情况 怎么做更稳
生产路径还钉着 4.5 本周内盘点 + Staging 切 5.5；11 月中前完成 canary
只有实验脚本 / 个人玩具调用 直接改 ID，顺手清掉 prefill 和 temperature
重度依赖 4.5 的语气或某套 JSON 习惯 先冻一批 golden cases，再迁；别裸换
只用 claude.ai，从不碰 API 本文可略读；订阅侧继续按 Claude Pro 教程 维护账号稳定即可
Bedrock / Vertex 用户 先查云厂商退休日，再套同一套参数改造

一句话：能改配置的人，这六周够用；等 11 月 30 日凌晨报警再改，最亏。

FAQ

Q：只改成 claude-sonnet-5-5 行不行？
A：多数老集成不行。至少检查 prefill、强制 tool、thinking 预算、采样参数，并用真实任务回归。

Q：11 月 30 日之后还能调 4.5 吗？
A：在 Anthropic 列出的平台上会失败。权重长期保存不等于对外可调用。

Q：Claude Code / Managed Agents 要改什么？
A：官方说 Managed Agents 多数只需改模型名；自建 Messages API 客户端要按迁移指南改参数。

Q：和 OpenAI 那波 API 下线有什么关系？
A：无关。OpenAI 10/23 旧快照是另一条线；两边各自 grep 各自的 ID。
