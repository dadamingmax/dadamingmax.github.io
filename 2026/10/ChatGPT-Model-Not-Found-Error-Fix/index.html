ChatGPT 突然提示 Model not found？可能和昨天 GPT-5.5 下架有关，教你解决

十月 15, 2026 ChatGPT

昨天（2026-10-14）OpenAI 把 GPT-5.5 从 ChatGPT、ChatGPT Work，以及用 ChatGPT 账号登录的 Codex 里撤了；今天（10-15）一堆人打开网页就撞上 Model not found / Model is not found / The model does not exist or you do not have access to it。

时间对得上，但别把所有同类报错都甩给“GPT-5 全家下架”——这次主要是 GPT-5.5 产品侧退役，不是整条 GPT-5 线，也 不等于 API 一起关。

可以先分清你卡在哪：网页/App 选不到或直接报 Model not found，和 API/工具返回 model_not_found，排查路径不一样。下面按场景一次说清。

一、昨天 OpenAI 到底下架了什么？

官方 Model Release Notes 写得很直：2026-10-14 起，GPT-5.5 从 ChatGPT、ChatGPT Work、Codex 退役；不影响 API。

Models 文档补了两句更细的：生效点是 太平洋时间中午（UTC 19:00）；用 API Key 登录的 Codex 会话不受影响。

ChatGPT 登录的 Codex：Plus / Pro / Business / Enterprise / Edu 可切到 gpt-6.1-sol（有的账号列表里也会看到 gpt-6-sol）；

Free / Go 桌面端切 gpt-6-luna。默认配置、自定义 Agent、定时任务、脚本里写死的 gpt-5.5 都要改。

两个容易传歪的点：

谣言 / 误读 实际
“GPT-5 系列全下架了” 这次是 GPT-5.5 产品侧退役；别把 5.1 / 5.4 / 5.6 一锅端
“API 也没了” 官方明确 API 保留；API Key 登录的 Codex 也不吃这波产品退役

网上有人把“昨天下架 → 今天全站 Model not found”连成一条因果，时间上说得通，但同一天还有浏览器只挂 Chrome、手机正常、登出免费档还能聊这类个案——说明 退役 + 缓存/路由/端侧 可能叠在一起，别只查一条线。

二、为什么模型下架会冒出 Model not found？

每条对话、每个 Codex 任务背后都要钉死一个模型 ID。产品侧把 GPT-5.5 撤掉之后，如果旧对话、工作区默认、自定义 Agent 或脚本还在指着 gpt-5.5，请求就会变成“找不到 / 没权限”——文案往往就是 Model not found。

Reddit / Codex 圈子里更扎心的是：项目默认还钉着 gpt-5.5，一发 prompt 就 404，灰掉、重试偶发成功，本质是配置没迁完，不是“玄学”。

但退役只是 可能原因之一。常见叠因：

可能原因 具体表现
旧模型退役 昨天正常，今天突然不可用；旧对话炸、新对话有时正常
旧对话 / 钉死配置 历史会话、Agent、定时任务仍指向 GPT-5.5
网页 / 客户端缓存 换浏览器或无痕就好；同账号 Chrome 挂、Edge 正常
端侧不一致 桌面 + 网页挂，手机 App 还能用
账号 / 工作区权限 套餐、额度、Business 进错 workspace
服务端瞬时异常 多模型、新旧对话一起挂，查 status
API / 第三方配置 模型 ID、Key 权限、Base URL 对不上

官方论坛里 10-15 当天就有人复现：对话搜索报 Model not found；有人 只有 Chrome 有问题，Edge 正常——典型缓存/客户端路径问题，不是账号被销。另有人桌面端和网页挂了两小时，手机 App 正常，也指向端侧而不是“号没了”。

三、ChatGPT 网页 / App：按这个顺序试

方法一：新建对话，切到当前可用模型

  1. 打开 ChatGPT，点新建对话。
  2. 打开模型选择器，选你账号现在还能点的档。
  3. 发一句简单测试。

旧对话还报错、新对话正常 → 多半是历史会话还挂着已撤模型。把要点复制到新对话继续用，别死磕那条旧线程。

方法二：强制刷新、重登、无痕

新建也挂的话：

  1. 强制刷新页面（或清站点缓存）。
  2. 退出账号 → 再登录。
  3. 用无痕窗口或换浏览器试一遍。

有人续费 Plus 之后新旧聊天仍 Model not found，换模型、开无痕也不行，但 Codex 还能用——说明不一定是“没付钱”，更像会话/路由或端侧状态卡住。

论坛 Chrome vs Edge 的差异，也支持先换客户端再怀疑账号。

方法三：核套餐和模型权限（别指望充值复活已退役模型）

Free / Go / Plus / Pro 可见模型不一样；Business / Enterprise 还受工作区开关影响。进产品后看：

  • 订阅是否正常、有没有额度/重置提示
  • 选择器里还有哪些可用模型
  • 团队账号是否进对了 workspace

模型已经正式退役，再充 Plus / 升 Pro 也不会把它变回来。 只有权限不足、额度打满、或你本来就该用更高档位时，升档才有意义。国内想稳定开 Plus / Pro，可走 cnmgpt.com；升完再回选择器核对，别把“充值”当成修 5.5 的开关。

方法四：查官方状态页

所有模型一起挂、新建也失败 → 先打开 status.openai.com。

有故障就等；没有再继续查账号、网络、客户端。同一条 Model not found 重试一百次通常没用——退役和权限问题重试修不好。

四、Codex 用户：先看登录方式

这波退役 覆盖用 ChatGPT 账号登录的 Codex（各套餐都一样）；API Key 登录的 Codex 不在这波产品退役里。

ChatGPT 登录且配置还写着 gpt-5.5 时，按官方现文换成：

套餐 建议替换（有则选）
Plus / Pro / Business / Enterprise / Edu gpt-6.1-sol（Enterprise / Edu 常需管理员先打开）
Free / Go（桌面 App） gpt-6-luna

同时扫一遍：默认模型、自定义 Agent、项目/工作区配置、定时任务、CLI -m / 脚本。有人提醒过：模型名写死在代码里，退役日当天就会批量变 bug——ID 放配置里。

编码工作流可对照站内 Codex 2026 实战指南。

五、API / 第三方工具报 model_not_found

典型响应：

这不等于“模型已从地球删除”，更常见是：

  1. 模型 ID 写错 —— 把 ChatGPT 里的显示名塞进 API 的 model
  2. Key / 项目没权限 —— Plus 订阅 ≠ API 自动开通同名模型
  3. 快照退役时间表 —— 与 10/14 产品退役是两条线：一批旧快照计划 2026-10-23 API 不可访问；另有 GPT-5 / o3 等较早快照计划 2026-12-11 退役。以 Deprecations 现文为准
  4. 第三方 Base URL —— 中转/兼容网关用了 OpenAI 的 slug，对端根本没有这个名字

最快自检（同一把 Key）：

列表没有 → 查拼写、权限、退役表；列表有仍 404 → 查端点、org/project 头、客户端 Base URL。列表有也不代表每个端点都支持该模型。

六、是不是账号被封了？

很多人第一反应是“号没了 / Plus 失效”。仅凭 Model not found 不能下这个结论。

也有付费用户吐槽：登录付费账号全挂，登出后免费档反而能聊——听起来像订阅坏了，更稳妥的理解是：付费会话路径还在摸已撤模型或坏路由，先按第三节排查。

简单对照：

现象 更该查什么
能登录，某个模型 / 旧对话报错 模型退役、切新对话、改配置
能登录，所有模型失败 status、缓存、换端、权限
API 单个模型 404 模型 ID、Key 权限、端点、Deprecations
明确提示停用 / 登不进去 再按账号限制走 Support

常规手段都无效：带完整报错截图和发生时间，走 ChatGPT 帮助中心。

七、总结：先分清场景，再决定要不要动订阅

  • 10/14 GPT-5.5 产品退役 和时间线吻合，值得优先排查；但不是所有 Model not found 的唯一解释。
  • ChatGPT 用户：新建对话 → 切可用模型 → 刷新/重登/换浏览器 → 核套餐与 status。
  • Codex：先分清 ChatGPT 登录还是 API Key；前者改 gpt-6.1-sol / gpt-6-luna，后者这波产品退役一般不动。
  • API：/v1/models + Deprecations；10/23、12/11 是另一张表，别和 10/14 混。
  • 找不到模型 ≠ 账号被封；ChatGPT 撤 5.5 ≠ GPT-5 全系 API 关停。
  • 已退役模型充值救不回来；

升级订阅 GPT Plus/Pro 可通过 cnmgpt.com 开通。

FAQ

Q：是不是 GPT-5 全系列都下架了？
A：不是。这次是 GPT-5.5 从 ChatGPT / Work / ChatGPT 登录的 Codex 退役。

Q：API 还能用 GPT-5.5 吗？
A：官方写明本次产品退役不影响 API；API Key 登录的 Codex 也不受这波牵连。具体以你 Key 的 /v1/models 为准。

Q：Codex 该换成哪个模型？
A：官方现文：Plus 及以上（含 Business / Enterprise / Edu）优先 gpt-6.1-sol；Free / Go 桌面端 gpt-6-luna。Enterprise / Edu 常需管理员启用。

Q：换浏览器好了，说明账号没事？
A：很大概率是。论坛有 Chrome 挂、Edge 正常的案例，优先清缓存/换端。

Q：充值 Plus 能让 GPT-5.5 回来吗？
A：不能。退役模型不会因续费复活；升档只解决权限/额度类问题。
